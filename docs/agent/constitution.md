# Kubera Constitution

Project Kubera follows the give rules and regulations:

1. Code is readable.
2. Code is maintainable.
3. Code is modular.
4. Code is well documented.
   - Functions are documented as comments following input and output examples.
   - Architecture is documented as markdown files.
   - Data flow and behaviours are document as markdown files.
   - Metrics and APIs are documented with examples.
5. Architecture is thoroughly clarified before any implementation.
6. Native libraries are preferred
   - If implementation with external libaries is easier, team is prompted of the reasons to use it as well as documented.
7. Testing is preferred
   - Unit testing tries to cover each functions for better code coverage
   - Module testing test the feature as a whole
